# 山顶搬家公司 · v0.5 灰盒

这是 v0.5 框架 第 10 节"首轮验证"的可玩切片：**山顶图的下段与前坪**，一个借用 O6 条件的教学单，加夜市 Boss B2；在同一张图上另外做了终章 B3"换季·公司上山"（§8），它不在首轮验证范围内，用来检验 B2 的摆法能不能成为终章的条件。二维俯视，用一点斜向抬升表示高度；数值全部是待校准的占位，不是成品画面，也不是实测参数。

它要回答的是 v0.5 §10 的 V1–V7：玩家能不能从稳度卡预测路线和到场侧，侧翻后说不说得出原因，连台带货是不是在所有条件下都最好，阵风是不是只剩等待，两人抬是自然合作还是被迫等人，侧翻后重新装车读起来是代价还是惩罚。自动测试和脚本机器人只能说明规则跑得通、账算得清，**不能回答这些问题**；要靠真人试玩，流程见 [PLAYTEST.md](PLAYTEST.md)。

## 开始玩

需要 Node.js 22 或更新版本，没有第三方依赖。

```sh
node server.mjs
```

浏览器打开 **http://127.0.0.1:4175**，填名字、选委托和主车配置，点"开门营业"。端口被占用时运行 `node server.mjs --port 4176`。

| 按键 | 作用 |
|---|---|
| WASD / 方向键 | 走路；在驾驶位时油门、倒车、转向 |
| 空格 | 刹车 |
| E | 搬起 / 放下货物；在车尾装车、卸车；把货摆上展开的台；从台上取货 |
| G | 推一个展开的台（可以带着货）；搭档也按 G 就变成两人抬；再按松手 |
| Q | 展开地上的折叠台；把一张空台折起来 |
| T | 把手里的高件（灯笼架、高茶柜）立起或放倒；空手时立起或放倒身边台上的高件 |
| R | 把手里的货绕着自己转四分之一圈（长件过门前先转到身前），或旋转正在推的整组 |
| F | 上车 / 下车 |
| M | 全图 |
| H | 收起 / 打开左右两块面板 |
| Esc | 菜单：换主车配置、叫救援、三单任选、照片墙、导出记录 |

画面下方的提示条会写出此刻每个键会做什么。提示由服务器按和按键同一套规则算出，提示里出现的键按下去就会那样做；装车前它会写出装上后的最高点和能不能过老山门，稳度卡最上面也多一行"装上后"。画面上还有一个标签指向货在哪里、或者手里的东西该送到哪里。按不成的那一项标成红色并写原因；推着的整组走不动时，提示条写出是什么挡着。开车到垭口前和垭口里，驾驶条写阵风此刻的状态和倒计时，以及这一车该走还是该等。

## 两单

**O6 茶馆八仙桌（教学单）**：六张八仙桌和一个高茶柜，从旧夜市广场的木器行送到山顶茶馆。高茶柜是整面玻璃门，只能立着运。茶馆巷口有两根石墩，限宽 2.2 m：伴行小车（1.9 m）开得进去，直接停茶馆前院，但一车只装得下两张方桌（或两张方桌加茶柜）；主车（2.3 m）一趟装得下全部，却只能停在垭口后停靠点，东西要人手搬一段进茶馆。装满、茶柜又立着时，发夹弯和阵风的建议速度都很低。可以主车一趟装满再人手搬，小车分几趟直接送到门口，或者主车运方桌、小车运茶柜。

**B2 夜市最后一车（Boss）**：四张折叠台、两件长棚架、八件摊货。四张台既是旧址装车的接驳面，也是新夜市的四个工作面：灯笼摊（前侧，两个公开位置任选其一）、糖水摊、烤串摊、公共服务面，每个都要"台 + 对应两件货"摆在工作面上，两个摊还要把棚架放到棚架位。灯笼架要立着才算摆好，立好就亮灯。公共服务面在一个围墙小院里，院门只有 1.4 m：单件和折起的台（端头朝前）进得去，展开的台和整组进不去。

**B3 换季·公司上山（终章）**：三股货流共用前坪和冬棚那一扇门——公司的五件东西（长招牌、两箱纪念物、B1 的旧店招牌、夜市送的灯笼架）从车库门口上山进旧气象站；夜市冬歇，十四件东西下山进旧夜市广场边的冬棚；冬棚里的两个货架和一条短长椅上山进新址。夜市保持 B2 结束时你们摆的样子（从 B2 的评价卡接着开）；直接开始时用"前侧摊位挡在气象站正门前"的摆法。开着的前侧摊位（台和货都摆好）前站着客人，搬着任何东西都过不去，正门等于被挡住：要么先撤这一摊，要么五件东西都走后门步道，从观景台的另一头绕进去。冬棚门只过得了折叠台。夜市送的灯笼架立着就亮；它比 B2 的灯笼架大，立着装在主车或伴行小车上都过不了老山门，只有低货台立着运得过去，连着灯笼立着运过垭口还要掐阵风。

## 这一版实现了什么

- **一条稳定规则。** 车、台、货共用外廓和稳度：稳度 = 底宽的一半 ÷ 重心高度，由实际摆放计算。稳度卡显示最高点、能不能过 3.0 m 的老山门、到场侧、两条路的弯道建议速度、垭口阵风建议，以及稳度数值本身。
- **弯道牌按当前装载显示建议速度。** 弯道牌立在来车右侧的路边；驾驶条提前看前方的弯，开得比建议快就变红。接近建议速度时车身吱嘎；超过后约两秒的抬轮预警（明显超速时约 1.3 秒）；继续不减速才侧翻。低于建议速度不会翻，没有随机侧翻。
- **侧翻后救援先卸后扶。** 车回到它所在路段的停靠点：广场和两条山路回入口停靠点，垭口前回垭口前停靠点，山顶一带回垭口后停靠点，不会被往山上送。车上的东西整组保持锁定，卸在停靠点旁固定的救援坪上，要重新装车。侧翻会自动播放三秒侧面回放（附一个小后视图）和原因标签，按 Enter 或 Esc 关闭，可存进照片墙。菜单里的"叫救援"给卡住的车用，后果和侧翻相同（货卸在救援坪上），抬轮预警中叫不了。
- **路边。** 浅角度擦到路边时，车贴着路边慢慢滑；顶住时原地以后轴为支点慢慢转向；卡住约 1 秒后自动往路中间挪一点；在墙角、门柱或山门前顶住时，按住 W 和方向，车会一点点往后退、车头转过来（第四轮试玩里这一招在路口内角大多不管用，还要再改）。
- **到场侧。** 过得了老山门的停近侧卸货带；过不了的停西坪。每个摊位都有一件 1.1 m 的货，四个摊位的整组在主车和伴行小车上都过不了，在低货台低段上都过得了（立着灯笼架的那一组除外），和 §7 一致；只把矮的货留在台上的"半整组"过得了。3.0 m 附近的高度显示到厘米。西坪与工作面隔着两级台阶：一个人推整组要绕到西端的缓坡，两个人可以直接抬上去。山门两个方向都限高：在近侧卸货带里只能装出得了山门的东西。
- **整组。** 一个人推的整组只走平地和缓坡（车尾坡也算），山路是坡，整组不能在路上推；两个人抬走得快，能上下两级台阶，任何一人松手都会稳稳放下，在台阶上松手会退回台阶下的平地。
- **垭口阵风。** 节奏固定：静 3 秒，风声变尖 2 秒，阵风 4 秒。三道挡风墙后不受风，每处能停一辆上山车、一辆下山车。阵风建议速度由受风面积和稳度计算，装得太高时只能在墙后等：从静止起步，一个"静 + 风声变尖"刚好够从一面挡风墙跳到下一面。阵风中车在垭口里，抬轮预警不会回落，开快了冲过去不比等风安全。
- **坡折与巷口。** 茶馆路上有一道坡折，低货台过不去（会刮底）；再往前是限宽 2.2 m 的巷口，主车不论哪种车床都进不去，伴行小车进得去。开到巷口前，驾驶条和稳度卡都会写明。
- **车床。** 主车车床 4.0 × 2.0 m，放得下一个展开的台（连货）或两张折叠台；低货台配置的前部低段 0.75 m 放一个整组，后段只放一件长件（可以悬出车尾）；伴行小车放一个小整组。都从车尾装，后装的先卸。车身和车尾坡都要在平地上，车尾和货之间不能隔着墙、护栏或台阶。
- **最多四人**，一辆主车加三辆伴行小车，停在入口停靠点。
- **摊位前留给客人的位置。** 2.5 m 以上的东西（棚架、公司招牌）不能拿进、搬进或放进前侧摊位前留给客人的位置（卸货带靠气象站的那一半），只能往外移；摊位开着（台和这一摊的货都摆好）时，搬着任何东西、推着整组都过不去，空手可以穿过；摊位撤掉（货取下、台折起）就能过。车也开不进那块位置，卸货带南侧留着 4.5 m 车道；前侧摊位也只在靠气象站的那一半才算摆好。
- **客户评价卡**只用本单实际记录的事件生成，例如在挡风墙后等了几阵风、谁先抢到近侧、哪组停到了西坪、灯笼架是不是立着上山的、前侧摊位摆在哪一侧。左侧的"搬移次数 H"和"手搬距离 M"只是记录，不是分数。

## 与 v0.5 文档的差别

这些是灰盒为了先跑起来做的简化，试玩后再决定去留：

- 二维俯视，驾驶是街机式的；"规则先于物理"，没有刚体模拟。
- 伴行车一开始就停在入口停靠点，没有"在安全停靠点领用"的步骤；不论人数都有三辆。
- 按 §10，O6 的货单和条件借到山顶图里：茶馆在垭口后的东侧，O6 与 B2 共用同一个垭口，没有单独的山腰短垭口。
- 没有经济、车库编辑和 O9。低货台在这个切片里的反对条件在 O6：它的车床装得少，要多跑一趟；茶馆路上还有一道**坡折**（低货台会刮底）。这道坡折是灰盒补的，设计只写了"坡折保留，只影响低货台的离地间隙"。
- B3 没有单独的车库场景，公司的五件东西放在旧夜市广场的车库门口；没有"全队坐主车一起出发"的确认，伴行车一开始就能用；冬棚放在旧夜市广场边的旧棚子东头。
- 山路一律算陡坡，整组不能在路上推，只能装车运；这是灰盒补的一条规则，文档只写了"平地和缓坡"。
- 状态每秒同步 10 次，客户端插值显示，没有本地预测；只在本机或可信局域网里测过。

## 和朋友测试

默认只接受本机连接。不同标签页或浏览器用房间码加入同一家公司，最多四人。在可信局域网测试时运行 `node server.mjs --host 0.0.0.0`，朋友打开 `http://<这台电脑的局域网 IP>:4175`，输入房间码。房主短暂掉线时模拟暂停，20 秒没回来就由还在线的伙伴接手做房主，原房主变成客人，15 秒内回来还在；暂时掉线的客人 15 秒后释放名额。同一台设备十分钟内最多开 8 家公司、同时开着最多 4 家，开了两分钟没人连上的公司会被关闭。放在反向代理后面时用 `node server.mjs --trust-proxy`，按 X-Forwarded-For 区分设备。服务重启后，页面会提示公司已关闭并回到开始页。
